# PPT 프로젝트

발표 자료를 만들기 위한 작업 공간입니다.
특정 도구에 묶이지 않도록 **원본 / 자원 / 결과물**을 분리한 구조로 잡았습니다.

## 폴더 구조

```
slides/
├── src/                 슬라이드 원본 (사람이 직접 편집하는 유일한 곳)
│   ├── 01-cover.md      표지
│   ├── 02-agenda.md     목차
│   ├── 03-content.md    본문
│   ├── 04-closing.md    마무리 / Q&A
│   └── theme/           테마·템플릿 (색, 폰트, 레이아웃)
├── assets/              슬라이드에 들어가는 자원
│   ├── images/          사진, 스크린샷, 배경
│   ├── icons/           아이콘, 로고
│   ├── fonts/           사용할 폰트 파일
│   ├── media/           영상, 오디오
│   └── charts/          차트 이미지
├── data/                원본 데이터 (엑셀, csv, 조사 자료)
├── notes/               발표 대본, 리서치, 참고 링크
├── scripts/             빌드·변환 스크립트
├── output/              최종 산출물 (.pptx / .pdf / .html)  ← 커밋 제외
└── archive/             이전 버전, 폐기한 시안
```

## 왜 이렇게 나누나

- **`src/`만 편집합니다.** 결과물(`output/`)은 언제든 다시 만들 수 있는 부산물이라
  덮어써도 아깝지 않습니다. 원본을 잃을 위험이 없어집니다.
- **`assets/`에 용량 큰 파일을 몰아둡니다.** `output/`과 함께 git에서 제외하면
  저장소가 가벼워집니다.
- **`data/`와 `charts/`를 분리합니다.** 숫자가 바뀌면 차트만 다시 그려 넣으면 됩니다.
- **`notes/`에 대본을 둡니다.** 슬라이드 글자와 말할 내용은 다릅니다.

## 작업 순서 (권장)

1. `notes/`에 목적·청중·발표 시간을 적는다.
2. `src/02-agenda.md`에 목차를 잡는다.
3. `src/`에 슬라이드를 채운다. 자원은 `assets/`에 넣는다.
4. `scripts/build.ps1`로 `output/`에 결과물을 만든다.
5. 발표 후 수정본은 `archive/`에 백업한다.

## 빌드

`scripts/build.ps1`은 설치된 도구를 자동으로 찾아 안내합니다.

```powershell
cd slides
.\scripts\build.ps1
```

## 파일 이름 규칙

- 슬라이드 원본: `번호-이름.md` (`03-content.md`)
- 자원: 소문자-하이픈 (`team-photo-2026.png`)
- 날짜가 있는 자료: `YYYYMMDD-이름` (`20260921-시장조사.pdf`)
